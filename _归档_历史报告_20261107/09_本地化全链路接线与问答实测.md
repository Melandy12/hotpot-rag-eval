# 本地化全链路接线与问答实测（2026-11-06）

| 环节 | 组件 | 端口 | 说明 |
|---|---|---|---|
| 检索 | SAG Wiki 本地服务（FTS5 + BM25 + Jev 判定） | 服务内部 | 108 片语料，免嵌入免离线模型 |

## 二、桌面端实测结论

### 搜索页：可用（可作答辩演示）

- 提问“黑水是咋回事，煮出来汤是黑的”→ 一行摘要“深入搜索 · 42 个文件 · 225 ms”
- 第 1 位 `CASE-2026-003 清油麻辣底料（BATCH-26-003）｜静置后出现明显分层底部有沉淀物`，右侧可直接展开原文表格，右上角「打开文档」
- 全程未联网
- 截图：`08_SAGWiki界面截图\sagwiki_search_heishui.png`

命令行同一路段（`sag.exe "黑水是咋回事，煮出来汤是黑的" <KB目录> --max-results 3`）第 1 位同样是 CASE-2026-003，说明检索通路健康。

### 问答页：能出答案，但检索工具参数有缺陷

现象与根因（来自 `conversations` 表的 `tool_calls` 原文）：

```
tool_name: search  server_name: SAG
query: {"query": "黑水 煮出 黑色 汤", "path": "", "top_k": 10}
is_error: true
error: 路径不可用：: 系统找不到指定的路径。 (os error 3)
```

即模型发出检索调用时 `path` 传了空串，SAG 解析空路径失败，检索直接返回错误，模型只能凭空作答——这正是第一次实测时它答“可能是水质问题”的原因。

界面侧另外两个坑（已确认、可绕过）：

1. 输入框不吃 `cu.type` 的键盘事件，必须点进框后 `set_clipboard` + `Ctrl+V` 粘贴；
2. 发送按钮点两次无响应，**用回车（Enter）提交才生效**。

已做的修复：

- 问答模型配置改到本地：`preferences.answer = {"url":"http://127.0.0.1:11434/v1","model":"qwen25-7b-local","has_key":true,"auth_mode":"bearer"}`
- 桌面端要求填 API 密钥才发请求，已写入占位密钥 `sk-local-ollama`（Ollama 不校验 Authorization，失败可用 `backup\credentials.json.bak_*` 回滚）
- `max_tool_calls` 由 0 改为 6（0 时问答链路不发起工具调用）

尚未解决：`path` 空串是应用侧构造工具参数的问题，只能靠「@引用文件」把具体文件塞进 scope 绕过；全库（全部文件）问答仍会踩这个错误。

## 三、自研本地问答链路（可替代桌面问答页做演示）

脚本：`03_评测\11_local_answer.py`（单题）、`03_评测\12_local_answer_batch.py`（批量）

流程：口语问法 → 词表扩展（`03_同义词扩展词典.json`）→ `sag.exe` 检索取证据原文 → 本地 7B 按“只依据证据、标注【证据N】”的约束生成答案。

### 5 题实测（`04_结果\12_本地问答链路_试跑.md`）

| 问题 | 结果 | 备注 |
|---|---|---|
| 黑水是咋回事，煮出来汤是黑的 | 可用 | 扩展词“汤色 发黑 色差 黑色碎屑 色素”把 009/008/035 三条真实案例拉回前 5；答案引用了 040（荧光灯色素氧化）与 009（光照致番茄红素降解） |
| 底料放两个月就不香了，味道跑掉了 | 可用 | 扩展词“香气 挥发性风味物质 风味稳定性 香气保留率”；命中 019/004/043/030 等风味劣化案例 |
| 酸价超标一般是什么原因造成的 | 可用 | 命中 CASE-2026-001，答出“夏季炒制温度 >165℃ 致牛油提前氧化 + 包装透氧率高” |
| 火锅底料成品该适用哪个食品安全国家标准 | 可用 | 正确答 GB 31644-2018，并说明该标准无理化指标限值 |
| 料渣水分高会带来什么问题 | 拒答 | 检索未召回料渣相关文档（语料缺“料渣水分”直接记录），属**词表/语料缺口**而非模型问题 |

关键观察：**同一题加不加词表扩展差别极大**。不加扩展时“黑水”命中的是分层、发黄、金属异味（完全跑题）；加扩展后才落到 009/008/035。这与前期 30 题集上 K=2 + M1 + 纯词法把口语 Hit@1 从 33.3% 拉到 80.0% 的结论一致。

## 四、仍未解决 / 需要拍板

1. **桌面问答页 `path` 空串**：应用侧缺陷，全库问答不可用；要么等官方修复，要么演示时统一走「@引用文件」或自研链路。
2. **7B 生成仍会轻度越界**：如“避免使用不合格色素”“定期检查原料是否变质”这类证据里没有的建议，答辩前应在提示词里进一步收紧，或对关键题做人工兜底。
3. **“料渣水分高”是非题**：语料里缺该主题的直接记录，需要补充工艺类文档或把词表扩到“脱水/炒制时间/水分活度”以外的表述。
4. **桌面端问答最长上下文 65536 tokens、单次输出 2048**：7B 在 8 GB 显存下 `num_ctx 8192` 实测正常，但证据过多时会挤爆窗口，建议 `top_k` 固定 ≤5。
5. **多网络切换会把下载打断**：本次换过中国杭州 / 韩国 / 印尼三种出口，`ollama pull` 在境外/国内均不稳定，最终走 ModelScope 单文件 GGUF + ollama `create` 才成功；模型层字节数与官方清单一致（4,683,073,952）。
